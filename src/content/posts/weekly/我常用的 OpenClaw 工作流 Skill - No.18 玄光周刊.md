## 我常用的 OpenClaw 工作流 Skill

用了 OpenClaw 三个多月，给我最大的感受是根本不知道这个工具的上限在哪里。几乎每天都会认识到新的概念，每周都会发现已有工作流的不足之处。其中 Skill 这个概念不得不提，它太重要了。

从我的理解来看，Skill 的本质就是让大模型把完成一个任务的一套复杂动作固定下来，形成套路或自动化的流水线。就像打游戏时，你控制的主角学会了新的技能，每个新技能其实就是基础动作组合成的一套固定连招。

这就是 Skill，有意思的是，AI 用的连招你是可以自创的，当然也可以让它自己创造。

自己用下来，最终留下了以下这些我认为相对实用 Skill 供你参考。总数量有很多，我按照用途分成三类，排序不分先后。

- 第一类，用来做信息收集整合的 Skill，定位是基础设施。
- 第二类，和自部署服务结合，自己定制设计的专用 Skill，定位是优化和加速生产力。
- 第三类，使用效果比较满意的第三方 Skill。

本期先介绍第一类。

**sys_status** ：查看当前系统状态。如果你和我一样，OpenClaw 安装在虚拟机中，这个 Skill 也是必然要有的。通常它也是和其他 Skill 互相配合使用的。

**api-usage** ：查询各家 Token 用量和余额信息，使用 OpenClaw 这种 Token 消耗大户，能及时查询到余额用量信息的重要性不言而喻。除了手动查询更方便以外，还可以结合自动计划任务，每天让它汇报整体的消耗量。

![目前我用的这三家|415](../_images/我常用的%20OpenClaw%20工作流%20Skill%20-%20No.18%20玄光周刊-1779519862582.webp)

我目前给 OpenClaw 用的一般就是上面这三家，其中 MiniMax 量大管饱，按调用次数计费，适合干脏活累活，DeepSeek V4 用来规划和设计执行方案。如果连它都搞不定，就会用 SiliconFlow 手动切换给 Kimi 2.6 或 GLM 5.1。他们家 [一直在发福利](https://cloud.siliconflow.cn/i/09r0o1Ax)，注册就有 16 元的额度，企业认证有 500 元，模型足够丰富和稳定。

这里需要补充，我用下来 OpenClaw 并不适合直接写代码，需要写代码的项目我会直接用 OpenCode 和 GPT，专业的事情交给专业的 Agent。在我看来，非职业程序员是用不到 Claude 的。

**check-update** ：检查版本更新。OpenClaw 的更新需要十分小心谨慎，初期我经历了两次盲目追新，都是升级到一半它自己就沉默了。

OpenClaw 的迭代速度非常快，但小毛病也非常多，所以就有了这个技能。它除了检查最新的版本，更重要的功能是在升级之前，自动搜索和总结当前版本到最新版之间新增了哪些功能？修复了什么问题？对我的工作流是否有实质性帮助。这是使用 OpenClaw 升级的时候一定要注意的，否则你就会发现大部分时间都花在折腾它本身上面。

**news-report** ：经典的 Agent 新闻摘要。我根据自己部署的服务做了一些定制，信息来源更侧重来自我的 miniflux 服务器上的 RSS 订阅、若干电报新闻频道和中文群组。这些信息即使是自己多年筛选出的关注领域，每天依旧会有成千上万条噪音。

这个技能的最终目标就是按照我喜欢的方式，过滤掉这些噪音。技术上也十分简单粗暴，第一批用正文三分之一内的关键词出现概率进行程序筛选，淘汰掉高时效性可不读的条目，第二批就是让 Agent 分身挨个阅读全文后进行充分语义理解，来找出我更大概率会关注的，值得一看的信息。

**cgart-analysis** : 深度分析，输出分析报告。顾名思义，这个 Skill 用来帮助我快速了解一个陌生的领域，产品，品牌，企业，人物等任何我感兴趣的对象。目前输出的效果内容整体已经相对成熟稳定，但设计版式还需要打磨。

![生成的研究报告局部](../_images/我常用的%20OpenClaw%20工作流%20Skill%20-%20No.18%20玄光周刊-1779603205424.webp)

以上这些 Skill 我习惯会直接把它们打包成一个计划任务，每天早晚上定时运行，汇报两次。

## 本期推荐

### Oh My OpenAgent — 重新定义 AI Agent 的开源工具箱

![图片取自原文页面](../_images/我常用的%20OpenClaw%20工作流%20Skill%20-%20No.18%20玄光周刊-1779036148975.webp)

🔗 https://ohmyopenagent.com

Oh My OpenAgent（omo）是一个开源的 AI Agent 工具链，前身是 oh-my-opencode。它将单个 AI Agent 转化为一支可协调的开发团队，支持 Claude、GPT、Gemini、Kimi、GLM、MiniMax 等多模型并行编排。

其核心理念是 "不绑定任何单一模型商"，通过多 Agent 协作、实时协调和 Side-by-side tmux 可视化来完成任务。维护者在 Discord 上完全公开构建过程，并声称 Anthropic 曾因该项目屏蔽 OpenCode。

社区反馈相当热烈，有人说 "它让我取消了 Cursor 订阅"。有兴趣深入了解可以查看其 AGENTS.md 文件，了解 11 个 Agent 的角色定义和生命周期钩子体系。

### GEO — 生成式引擎优化，SEO 的下一个战场

![图片取自原文页面](../_images/我常用的%20OpenClaw%20工作流%20Skill%20-%20No.18%20玄光周刊-1779036210576.webp)

🔗 https://www.digital4design.com/blog/what-is-geo-in-2026

GEO（Generative Engine Optimization，生成式引擎优化）是 2026 年迅速崛起的一个概念。它不同于传统 SEO 依赖外链和关键词密度，而是转向对 AI 系统的优化——让模型能够准确理解和引用你的内容。

核心策略包括：技术准备、提示词研究、答案优先设计、引用就绪的内容、基于提及的权威性、智能内链、片段优化和持续反馈。结构化数据（Schema Markup）在 GEO 中是必选项，而非加分项。

对于内容创作者来说，这意味着流量不再是唯一的衡量指标，内容在 AI 生成答案中的引用率和可验证性变得更加重要。

### AI 时代生存策略 — 关于多样性、跨界与领域判断

🔗 https://www.zhihu.com/question/268078103/answer/2026420567713039329

这篇内容从物理学热力学、控制论和演化博弈论出发，分析大模型平台与普通人之间的关系。其核心观点是：AI 平台是一个耗散结构，人体、企业、国家同样遵循这一系统逻辑。

应对策略上，文章建议增加自身多样性（跨界能力）和避免与 AI 正面硬刚。对于被 AI 跳跃式替代的领域，唯一理性选择是尽快切换赛道。同时从热力学角度看，判断一个领域是否萎缩的标准是：AI 对该领域优质数据养料的输入是否大于输出。

### 2026 设计趋势 — 从极简到大胆，视觉设计的方向在变

![](../_images/我常用的%20OpenClaw%20工作流%20Skill%20-%20No.18%20玄光周刊-1779036673128.webp)

🔗 https://www.behance.net/gallery/239027109/Design-Trends-2026

Behance 发布的 2026 设计趋势报告中，一个显著变化是极简主义开始与大胆排版共存——干净的布局配上粗体字和强对比色彩。这意味着 " 极简 " 不再等于 " 无聊 "，而是在克制中寻求视觉冲击力的突破。

报告中还提到 2026 年的设计更注重个性表达和情感共鸣，在 AI 工具快速普及的背景下，手工质感、纹理细节和有意识的设计决策反而成为差异化竞争力。

### Buzz — 离线音频转录与翻译工具

![Buzz 界面](../_images/我常用的%20OpenClaw%20工作流%20Skill%20-%20No.18%20玄光周刊-1779036946164.webp)

🔗 https://github.com/chidiwilliams/buzz

Buzz 是一款完全离线的音频转录和翻译工具，由 OpenAI 的 Whisper 驱动。它支持在本地计算机上处理音频文件，无需上传到云端，保护隐私的同时适合网络受限环境。

相比许多在线转录服务，Buzz 的优势在于本地运行、可定制模型选择和多语言翻译支持。对于播客爱好者、会议记录或需要处理敏感音频内容的用户来说，是一个值得关注的开源选项。我自己用就是把很多没时间听，但是感兴趣的人物访谈播客直接下载到本地丢进去，通常一个三小时左右的超长播客，用 5070Ti 加速转文本 5 分钟就处理好了，然后直接让 Agent 去梳理出有意思的观点和案例等有价值的信息，还是很不错的。
